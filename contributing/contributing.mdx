## Contribution Types

### Bug Reports

When reporting bugs, please include:

<AccordionGroup>
  <Accordion title="Required Information">
    - **Clear description** of the bug - **Steps to reproduce** the issue -
    **Expected vs actual behavior** - **Environment details** (OS, browser,
    Node.js version) - **Screenshots or error logs** if applicable
  </Accordion>
</AccordionGroup>

### Feature Requests

When requesting features, please provide:

- **Problem description** - What problem does this solve?
- **Proposed solution** - How should it work?
- **Use cases** - Who would benefit from this?
- **Mockups or examples** if applicable

### Code Contributions

#### Pull Request Process

1. **Fork the repository**
2. **Create a feature branch**: `git checkout -b feature/amazing-feature`
3. **Make your changes** following our coding standards
4. **Add tests** for new functionality
5. **Update documentation** if needed
6. **Commit your changes**: `git commit -m 'Add amazing feature'`
7. **Push to your fork**: `git push origin feature/amazing-feature`
8. **Open a Pull Request**

#### Code Standards

<AccordionGroup>
  <Accordion title="Frontend Standards">
    - Follow the [Frontend Architecture Guide](/frontend/architecture) - Use
    TypeScript for all code - Follow naming conventions (`.component.tsx`,
    `.hook.ts`, etc.) - Write tests for business logic - Use Prettier and ESLint
  </Accordion>
  <Accordion title="Backend Standards">
    - Follow NestJS best practices - Use TypeScript for all code - Write unit
    and integration tests - Follow API design patterns - Update OpenAPI
    documentation
  </Accordion>
  <Accordion title="AI/ML Standards">
    - Follow Python PEP 8 style guide - Write comprehensive tests - Document
    model performance metrics - Use MLflow for experiment tracking - Update
    pipeline documentation
  </Accordion>
</AccordionGroup>

## Development Workflow

### Branch Strategy

We use the following branch naming conventions:

- `feature/description` - New features
- `fix/description` - Bug fixes
- `docs/description` - Documentation updates
- `refactor/description` - Code refactoring
- `test/description` - Test improvements

### Commit Messages

Follow the [Conventional Commits](https://conventionalcommits.org/) specification:

```
type(scope): description

[optional body]

[optional footer]
```

Examples:

- `feat(frontend): add user dashboard component`
- `fix(backend): resolve authentication token expiry issue`
- `docs(ai): update pipeline documentation`

### Testing Requirements

<AccordionGroup>
  <Accordion title="Backend Testing">

    endpoints - Database tests for data operations - Authentication and
    authorization tests

  <Accordion title="AI/ML Testing">
    - Unit tests for data processing functions - Integration tests for ML
    pipeline - Performance tests for API endpoints - Model evaluation tests
  </Accordion>
</AccordionGroup>

## Code of Conduct

We are committed to providing a welcoming and inclusive experience for everyone. Please read and follow our [Code of Conduct](https://github.com/opensource-together/opensource-together/blob/main/CODE_OF_CONDUCT.md).

### Key Principles

- **Be respectful** and inclusive
- **Be constructive** in feedback
- **Be collaborative** and supportive
- **Be patient** with newcomers
