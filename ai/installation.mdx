This guide explains how to install, configure, and deploy the OST AI Engine platform, with a focus on centralized configuration, multi-language management, Dockerization, and Dagster orchestration.

## Requirements
- OS: Linux, macOS, Windows
- Python: 3.11+
- Go: ≥ 1.22 (Dockerfile uses 1.22.3)
- Node.js (for Prisma)
- Docker

## Centralized Configuration & Mapping

Project configuration is centralized in `config/cfg.yaml`, automatically generated by `config/cfg.py` from environment variables and simple business logic.

- **Why YAML?** Readable by Python, Go, and Node.js, so the whole pipeline shares a single source of truth (tokens, queries, limits, cron, etc.).
- **Workflow:**
    1. Define variables in `.env` (see `.env.example`).
    2. On startup/build, `config/cfg.py` creates/updates `config/cfg.yaml`.
    3. Dagster, Go scrapers, and Prisma consume YAML config.

Mapping from raw scrapers to the unified Project model is centralized in `src/dagster/config/map/mapping_map.py` (static dictionaries for GitHub and GitLab). These mappings are imported directly in assets—no Dagster resource needed.

**Example cfg.example.yaml:**
```yaml
DATABASE_URL: postgresql://postgres:postgres@ost-db:5432/ost_dev
GITHUB_ACCESS_TOKEN: ...
GITLAB_ACCESS_TOKEN: ...
GITHUB_SCRAPING_QUERY: stars:>100 stars:<500 created:>=2025-10-11 is:public archived:false
GITHUB_TOP_N: 30
```

## Environment Variables

Copy `.env.example` to `.env` and fill in the values:
```ini
OST_CONFIG_PATH=config/cfg.yaml

DATABASE_URL=postgresql://ai-engine:ai-engine@localhost:7777/ai-engine
POSTGRES_DB=ai-engine
POSTGRES_USER=ai-engine
POSTGRES_PASSWORD=ai-engine

GITHUB_ACCESS_TOKEN=your_github_access_token_here
GITLAB_ACCESS_TOKEN=your_gitlab_access_token_here
```

**Propagation:**
- Python loads variables via `dotenv`.
- `config.py` injects them into YAML.
- Go and Dagster read config from YAML (never directly from `.env`).

| Variable              | Description                  | Example |
|-----------------------|------------------------------|---------|
| DATABASE_URL          | PostgreSQL connection URL    | postgresql://db_user:db_password@localhost:port/db_name |
| POSTGRES_DB           | Database name                | db_name |
| POSTGRES_USER         | Database user                | db_user |
| POSTGRES_PASSWORD     | Database password            | db_password |
| GITHUB_ACCESS_TOKEN   | GitHub API token             | your_github_access_token_here |
| GITLAB_ACCESS_TOKEN   | GitLab API token             | your_gitlab_access_token_here |

## Dockerization & Multi-language Build

The Dockerfile builds the entire stack end-to-end:
- Installs system deps, Poetry, and Go (1.22.3)
- Installs Python deps via Poetry
- Copies source and Prisma files, generates Prisma client
- Copies centralized config directory
- Compiles Go scrapers to `/app/github-scraper` and `/app/gitlab-scraper`
- Sets `DAGSTER_HOME` and exposes the Dagster UI port (3000)

**Dockerfile excerpt (simplified):**
```dockerfile
FROM python:3.11-slim AS base

RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential git curl ca-certificates gcc libpq-dev wget unzip \
    && rm -rf /var/lib/apt/lists/*

ENV GO_VERSION=1.22.3
RUN wget https://go.dev/dl/go${GO_VERSION}.linux-amd64.tar.gz \
    && tar -C /usr/local -xzf go${GO_VERSION}.linux-amd64.tar.gz \
    && rm go${GO_VERSION}.linux-amd64.tar.gz
ENV PATH="/usr/local/go/bin:$PATH"

RUN pip install poetry
WORKDIR /app

COPY .env .env
COPY pyproject.toml poetry.lock ./
RUN poetry install --no-root --only main

COPY src/ src/
COPY prisma/ prisma/
RUN poetry run prisma generate

COPY config/ config/
ENV GOARCH=arm64
RUN cd src/services/go/github && go build -o /app/github-scraper main.go
RUN cd src/services/go/gitlab && go build -o /app/gitlab-scraper main.go

ENV DAGSTER_HOME=/app/src/dagster
EXPOSE 3000
```

## Dagster Orchestration & Cron

- The main job (`github_scraper_job`) is scheduled from code using `PipelineConfig().github_scraper_cron` (e.g., `0 */6 * * *`).
- Dagster config (`src/dagster/dagster.yaml`) controls instance settings (storage, logs, etc.).
- Assets are modular: Go scrapers run via `subprocess` from assets, configuration comes from the `config` resource.

**Dagster local launch** :
```bash
export DAGSTER_HOME="$PWD/src/dagster"
poetry run dagster dev -m src.dagster.definitions --host 127.0.0.1 --port 3000
```
Accès UI Dagster : [http://localhost:3000](http://localhost:3000)

## Automated config regeneration (cfg_cron.py)

To ensure the centralized YAML config (`cfg.yaml`) is always up-to-date, OST AI Engine includes an automated Python cron script: `scripts/cfg_cron.py`.

This script runs periodically (default: every day at 03:00, system timezone) and:
- Loads environment variables from `.env` using `dotenv`
- Resolves config paths relative to the project root
- Executes `cfg.py` to regenerate `cfg.yaml`
- Prints verbose logs and checks if the YAML was generated

- The script uses the system timezone for scheduling.
- You can change the hour in `schedule.every().day.at("03:00")`.

This ensures all services (Dagster, Go, Prisma) always consume the latest config.
