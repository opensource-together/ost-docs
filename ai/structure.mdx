# Project Structure

- `src/dagster`: Orchestration, assets, centralized configuration
- `src/infrastructure/services/go`: GitHub/GitLab scrapers (Go)
- `prisma`: Database modeling, migrations
- `docs`: Technical documentation
- `.env`: Environment variables
- `docker-compose.yml`: Service deployment

## Dagster Structure Overview

- `src/dagster/assets.py`: Dagster asset definitions. Each asset is a pipeline step (data extraction, transformation, loading, or Go scraper integration).
- `src/dagster/definitions.py`: Central file for Dagster jobs, schedules, and sensors. Register all assets, set up pipeline schedules (cron jobs), and define event-based triggers here.
- `src/dagster/dagster.yaml`: Main Dagster config file. Controls logging, storage, and execution environments.
- `src/dagster/config/`: Centralized config and mapping files:
    - `config.py`: Python module to load, validate, and generate the shared YAML config for all languages.
    - `github_mapping.py`: Maps GitHub data to pipeline assets, customizable for your data model.

The `src/dagster` folder is the orchestration core for all data workflows. It manages pipeline definitions, asset registration, configuration, and environment separation. To add or update a pipeline:
1. Create or edit assets in `assets.py` (Python or Go integration).
2. Register them in `definitions.py`.
3. Adjust settings in the config files as needed.
4. Schedules and sensors in `definitions.py` automate pipeline runs and event handling.

**Config workflow:**
- All config is centralized in `config.yaml`, generated by `config.py` from `.env` variables and business logic.
- Both Python and Go components read from the YAML for consistent parameters.

**Asset separation:**
- Python assets handle orchestration, transformation, and DB logic.
- Go scrapers are integrated as assets for high-performance data ingestion.
