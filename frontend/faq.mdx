## General Questions

<AccordionGroup>
  <Accordion title="What is the frontend architecture?">
    The frontend uses a **feature-based architecture** with Next.js 15,
    TypeScript, and hybrid state management (TanStack Query + Zustand). Each
    feature is an autonomous module containing components, hooks, services,
    stores, validations, and types. Learn more in our [Architecture
    Guide](/frontend/architecture).
  </Accordion>

<Accordion title="Why feature-based architecture?">
  Feature-based architecture provides: - **Better maintainability** - Related
  code is co-located - **Improved scalability** - Easy to add new features -
  **Clear separation of concerns** - Each feature is self-contained - **Team
  collaboration** - Multiple developers can work on different features
</Accordion>

  <Accordion title="What technologies are used?">
    - **Framework**: Next.js 15 with App Router - **Language**: TypeScript -
    **Styling**: Tailwind CSS - **State Management**: TanStack Query (server) +
    Zustand (client) - **Forms**: React Hook Form with Zod validation - **UI
    Components**: Radix UI primitives - **Icons**: Heroicons
  </Accordion>
</AccordionGroup>

## Development Questions

<AccordionGroup>
  <Accordion title="How do I add a new feature?">
    1. Create a new directory under `src/features/[feature-name]/`
    2. Add the required subdirectories: `components/`, `hooks/`, `services/`, etc.
    3. Follow the naming conventions (`.component.tsx`, `.hook.ts`, etc.)
    4. Implement your feature following the architecture principles
    5. Add tests and documentation
    
    See the [Architecture Guide](/frontend/architecture) for detailed instructions.
  </Accordion>
  
  <Accordion title="How do I handle API calls?">
    Use TanStack Query for all API calls:
    
    ```typescript
    // In a hook file
    export const useProjects = () => {
      return useQuery({
        queryKey: ['projects'],
        queryFn: () => projectsService.getAll(),
        staleTime: 5 * 60 * 1000, // 5 minutes
      })
    }
    ```
    
    Never make API calls directly in components - always use business logic hooks.
  </Accordion>
  
  <Accordion title="How do I manage client state?">
    Use Zustand for client state (UI state, user preferences):
    
    ```typescript
    // In a store file
    interface UIState {
      sidebarOpen: boolean
      setSidebarOpen: (open: boolean) => void
    }
    
    export const useUIStore = create<UIState>((set) => ({
      sidebarOpen: false,
      setSidebarOpen: (open) => set({ sidebarOpen: open }),
    }))
    ```
  </Accordion>
  
  <Accordion title="What's the difference between server and client state?">
    - **Server State** (TanStack Query): Data from APIs, cached, synchronized
    - **Client State** (Zustand): UI state, user preferences, temporary data
    
    Never duplicate data between them. Use events or optimistic updates for synchronization.
  </Accordion>
</AccordionGroup>

## File Naming Questions

<AccordionGroup>
  <Accordion title="What are the file naming conventions?">
    All files follow strict naming conventions: - `.component.tsx` - UI
    components - `.view.tsx` - Main pages/views - `.form.tsx` - React Hook Form
    components - `.hook.ts` - Business logic hooks - `.service.ts` - API
    calls/services - `.store.ts` - Zustand stores - `.schema.ts` - Zod schemas -
    `.type.ts` - TypeScript types Use kebab-case for file names and PascalCase
    for TypeScript exports.
  </Accordion>

<Accordion title="Where should I put shared components?">
  Shared components go in `src/shared/components/`. These are reusable UI
  components that can be used across multiple features. Feature-specific
  components go in `src/features/[feature-name]/components/`.
</Accordion>

  <Accordion title="How do I organize imports?">
    Imports are automatically organized by Prettier: 1. Third-party modules 2.
    Config files (`@/config/`) 3. Global types (`@/types/`) 4. Shared code
    (`@/shared/`) 5. Feature code (`@/features/`) 6. App code (`@/app/`) 7.
    Relative imports (`./`)
  </Accordion>
</AccordionGroup>

## Performance Questions

<AccordionGroup>
  <Accordion title="How do I optimize performance?">
    - Use React.memo for expensive components - Implement proper dependency
    arrays in useEffect - Use TanStack Query's intelligent caching - Optimize
    bundle size with dynamic imports - Use Next.js Image component for images -
    Implement proper error boundaries
  </Accordion>

<Accordion title="How do I handle large lists?">
  For large lists, consider: - **Virtualization** with libraries like
  react-window - **Pagination** with TanStack Query - **Infinite scrolling**
  with useInfiniteQuery - **Lazy loading** of non-critical items
</Accordion>

  <Accordion title="How do I debug performance issues?">
    Use these tools: - **React DevTools Profiler** - Identify slow components -
    **TanStack Query DevTools** - Monitor API calls and caching - **Next.js
    Bundle Analyzer** - Analyze bundle size - **Lighthouse** - Performance
    audits
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Common build errors">
    - **TypeScript errors**: Run `pnpm type-check` to identify issues - **Import
    errors**: Check import paths and file extensions - **Environment
    variables**: Ensure `.env.local` is properly configured - **Dependency
    issues**: Clear `node_modules` and reinstall with `pnpm install`
  </Accordion>

<Accordion title="Common runtime errors">
  - **Hydration errors**: Check for server/client mismatches - **State errors**:
  Ensure proper state initialization - **API errors**: Check network requests in
  DevTools - **Routing errors**: Verify Next.js routing configuration
</Accordion>

  <Accordion title="How do I debug issues?">
    1. Check browser console for errors 2. Use React DevTools for component
    debugging 3. Use TanStack Query DevTools for API debugging 4. Check network
    tab for failed requests 5. Use Next.js development mode for detailed error
    messages
  </Accordion>
</AccordionGroup>
